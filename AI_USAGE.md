# AI Usage

## Tools used and what for

- **Claude Code (Claude Opus 5.5)** in the terminal, across two sessions. The working log below has the details.
  - **Planning:** read the brief, drafted `CLAUDE.md` and the phased plan (kept in `PLAN.md` from session 2), and proposed the concurrency design: conditional updates in one transaction, with the expected status as the concurrency token.
  - **Code:** wrote the API (EF Core model, migrations, seed data, `TransferService`, ProblemDetails errors), the 30 integration tests, and the React screen.
  - **Checking:** ran ad hoc concurrent requests against the running API, broke the code on purpose to confirm the tests fail (written up in the README), and drove the screen in headless Chrome with throwaway Playwright scripts that are not in the repo.
  - **Docs:** drafted the README and this file from the working log as each phase finished.

## Where the AI was wrong or unhelpful, and how I noticed

**A query that would have thrown at runtime (Phase 2).** To build the "not enough stock" message, the AI read product names with `ToDictionaryAsync(s => s.ProductId, s => s.Product.Name)`. The element selector of `ToDictionaryAsync` runs on the client, after the query, and `Product` was not loaded, so the first over-stock dispatch would have thrown instead of returning the 409 message. It compiled and looked right. It was caught by reviewing the code before the first run, and fixed by projecting the name in the query first (`Select(s => new { s.ProductId, s.Product.Name, s.Quantity })`). The over-stock test in `TransferWorkflowTests` now covers that path.

Other real cases from the log:
- **A version clash (Phase 3):** the first test build failed with CS1705, because EF Core 10.0.13 reached the API only through a `PrivateAssets` design package, so the tests resolved an older version. Caught by the build, and fixed by pinning `Microsoft.EntityFrameworkCore.Relational`.
- **Discarding its own work (Phase 5):** to undo a deliberate break of `TransferService.cs`, the AI ran `git checkout --` on the file, which also threw away its uncommitted Phase 5 changes there. It had copied the file first, so it restored it, checked the diff and re-ran the tests.
- **False failures in its own check scripts (Phases 4 and 5):** the browser scripts read the page before it had loaded or reloaded, and used a Playwright call that does not report disabled `<option>` elements. The app was right each time; inspecting the page showed it, and the scripts were fixed.
